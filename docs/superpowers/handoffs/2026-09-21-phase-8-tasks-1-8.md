## 3. Four things that will bite, in order of how much they will cost you

### 3.1 The API cannot start, and that is expected

Task 4 added a column and task 6 added three tables to the model. **`Migrations/` is deliberately
untouched** — task 19 regenerates the single `InitialCreate` once, after every schema change has
settled, and drops the local database with the owner's permission.

Until task 19 runs: `dotnet build` works, the API does not start, no check script can run, and no
browser walkthrough is possible. Do not "fix" this by regenerating the migration early; doing it
twice is the thing the single-migration rule exists to prevent.

### 3.2 The test project does not compile — 202 errors, and the plan does not allocate work for it

`dotnet build DiplomaTracker.Api.Tests` reports **202 errors (106 CS7036, 96 CS8130) across exactly
three files**: `DepartmentServiceTests.cs`, `FacultyServiceTests.cs`, `GroupServiceTests.cs`.

Cause: task 2 added a `Guid administratorId` parameter to 21 service methods and an `ILogger<T>`
constructor parameter to several services; task 6 changed `GroupService`'s constructor and
`DeleteGroupAsync`'s signature. **Every failure is a call site missing an argument. Not one is an
assertion about changed behaviour.**

Task 19 step 6 says "all 56 existing tests pass", which cannot happen as written. The ruling made
on 2026-09-21: fix the three files mechanically **at task 19, before step 6** — pass a `Guid` for
`administratorId`, `NullLogger<T>.Instance` for the logger, `CancellationToken.None` and an
administrator id to `DeleteGroupAsync`. No assertion changes, no new tests; this is not the
end-of-project testing pass. It was deliberately not done earlier so it is done once, after every
signature in the plan has settled.

### 3.3 The archive shares storage keys with live files

An `ArchivedFile` names the **same** `StorageKey` as the live `SubmissionFile` it was copied from.
The archive never copies bytes. The rule that follows, and that every future change must respect:

> A stored file is deleted only when nothing points at it any more.

`ArchiveService.PurgeGroupAsync` is the only code in this phase that deletes a blob, and it checks
both `SubmissionFiles` and other groups' `ArchivedFiles` before doing so. Deleting a
still-referenced blob would destroy a live student's submitted work. A blob that cannot be removed
logs a warning and does not fail the purge.

### 3.4 Group deletion now deletes student accounts

This is the only place in the system where a student account is deleted. A group with even one
**active** student is still refused (`group.hasStudents`); a group whose remaining students are all
**archived** deletes those profiles and their user accounts, after their work and their full record
are in the archive. The owner approved this on 2026-09-21. It is irreversible by design — the
archive is what makes it acceptable.

## 4. Rulings made on the owner's behalf

Every one is in the ledger; reproduced here because the ledger does not travel.

1. **Task 2 does not touch `GroupService.DeleteGroupAsync`.** Task 6 owns that signature and adds
   its own log line. — One task per signature. — Cost if wrong: none.
2. **Task 14 may add `topics.rejectedNoComment`** to the translation files although task 13 owns
   the translation blocks. — The key exists only to serve task 14's change. — Cost if wrong: a key
   added one task later than the tidy place for it.
3. **Task 13 must end with a clean `tsc`, `lint` and `i18n:check`**, performing the three minimal
   call-site updates its own step 8 offers as an option. — "The frontend build is clean at the end
   of every task" is a global constraint, and a knowingly-red task hides any *other* error that
   appears in the same window. — Cost if wrong: a few lines written in task 13 and replaced in
   tasks 14–15.
4. **The `MaxCharactersInDocument` cap is restored to the shared inspector.** The plan's
   `OfficePackageInspector` dropped it; phase 6's security fix wave had added it ("M2 (sec)"). The
   per-entry length budget bounds a part's size, not how many characters an `XmlReader` will stream
   out of it. — Cost if wrong: none, it is a ceiling far above any real document. **Found by
   reading the deleted code, not by a reviewer.**
5. **An in-file lookalike duplicate reports `RowDuplicateNumber`, not `RowNumberEmailMismatch`.**
   The parse-time check now keys on the canonical form. — The other message sends a registrar
   looking for a student who does not exist; the clash is with an earlier line of the file they are
   uploading. — Cost if wrong: none, both refuse the row.
6. **The test project is fixed at task 19, not now** (§3.2 above). — Cost if wrong: task 19
   discovers more call sites than those three files. The count is measured, not estimated.
7. **`DocumentTemplateService.DeleteAsync` catches `DbUpdateConcurrencyException`.** Adding
   `RowVersion` put the token in the DELETE's WHERE clause, so deleting a template someone just
   replaced began answering 500. It could not throw before this task, so it is a regression
   introduced here. — Cost if wrong: a rare race answers 500 instead of 409.
